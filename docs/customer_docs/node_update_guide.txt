================================================================
         NUCLEUS NODE UPDATE GUIDE
================================================================

PURPOSE: Update a deployed Nucleus node to the latest software 
from the Git repository while keeping your existing mesh 
configuration intact.

This update adds two new configuration variables:
  • USB_HUB_POWER_CYCLE — fixes Meshtastic radio lockups on boot
  • COT_BRIDGE_ENABLED  — enables ATAK CoT bridging over LoRa

We'll also disable the mosquitto service which has been 
interfering with OpenTAK Server nodes.


PREREQUISITES
─────────────
  • A computer on the same network as the node (Wi-Fi AP or Ethernet)
  • A terminal app (Terminal on Mac/Linux, PowerShell or PuTTY on Windows)


================================================================
STEP 1 — SSH INTO THE NODE
================================================================

Open your terminal and run:

    ssh natak@0021-nucleus.local

When it asks for a password, type:

    52235223

(You won't see the password as you type — that's normal. 
Just type it and press Enter.)

*** IMPORTANT: 52235223 is also the "sudo" password. ***
Any time a command below starts with "sudo" and asks for 
a password, type 52235223

If it asks "Are you sure you want to continue connecting?" 
type "yes" and press Enter.

You should see a prompt like:  natak@nucleus:~$
You're in.


================================================================
STEP 2 — PULL THE LATEST CODE
================================================================

Run these two commands one at a time:

    cd ~/Nucleus_OS

    git pull

You should see files being updated. If it says "Already up to 
date" that's fine — continue anyway.


================================================================
STEP 3 — BACK UP YOUR MESH CONFIG
================================================================

Your mesh.conf has all your node's unique settings (IPs, mesh 
name, passwords). We need to protect it before deploy overwrites it.

    sudo mv /etc/nucleus/mesh.conf /etc/nucleus/mesh.bak.conf


================================================================
STEP 4 — INSTALL NEW PACKAGES
================================================================

    cd ~/Nucleus_OS

    sudo ./install-packages.sh

This may take a few minutes. Wait for it to finish completely.


================================================================
STEP 5 — RUN THE DEPLOY SCRIPT
================================================================

    sudo ./deploy.sh

Wait for "Deployment complete." to appear.


================================================================
STEP 6 — RESTORE YOUR MESH CONFIG
================================================================

The deploy just copied a fresh template mesh.conf with default 
values. Remove it and put your real config back:

    sudo rm /etc/nucleus/mesh.conf

    sudo mv /etc/nucleus/mesh.bak.conf /etc/nucleus/mesh.conf


================================================================
STEP 7 — ADD THE NEW CONFIG VARIABLES
================================================================

Your restored mesh.conf is from an older version and is missing 
two new variables. We need to add them to the bottom of the file.

Open the file:

    sudo nano /etc/nucleus/mesh.conf

HOW TO NAVIGATE IN NANO:
  • Use arrow keys to move around
  • Scroll to the very bottom (hold down arrow, or Ctrl+End)

At the very bottom, AFTER the last line, paste these two blocks:

─── copy everything between the dashed lines ───────────────────

# USB Hub Power Cycle — Meshtastic radio lockup workaround
# Power-cycles all USB devices on hub 1-1 at boot to recover a crashed
# RAK4631 Meshtastic radio. Only enable on nodes that experience
# Meshtastic radio lockups on boot.
USB_HUB_POWER_CYCLE=false

# ATAK CoT Bridge Configuration
# Bridges ATAK multicast CoT to/from Meshtastic LoRa
# When true, cot-bridge.service runs and the radio is in bridge mode
# When false (default), the radio is left in BLE mode for phone app
COT_BRIDGE_ENABLED=false

─── end of paste ───────────────────────────────────────────────

HOW TO SAVE AND EXIT NANO:
  1. Press Ctrl+O (the letter O, not zero) to save
     → It asks for a filename — just press Enter to confirm
  2. Press Ctrl+X to exit


================================================================
STEP 8 — DISABLE MOSQUITTO
================================================================

    sudo systemctl disable --now mosquitto

If you see "Unit mosquitto.service not found" — that's fine, 
it just wasn't installed on this node. Move on.


================================================================
STEP 9 — REGENERATE SYSTEM CONFIGS
================================================================

    sudo /opt/nucleus/bin/config_generation.sh

You should see "Configuration files generated successfully."


================================================================
STEP 10 — REBOOT
================================================================

    sudo reboot

Your SSH session will disconnect. That's expected.
Wait about 60-90 seconds for the node to come back up.


================================================================
STEP 11 — RECONNECT AND VERIFY THE COT BRIDGE
================================================================

SSH back in:

    ssh natak@0021-nucleus.local

Password: 52235223

Now watch the CoT bridge log in real time:

    sudo journalctl -u cot-bridge -f

This shows a live scrolling log. LEAVE THIS RUNNING and then:

  1. Connect an ATAK device (phone/tablet) to the node's 
     Wi-Fi access point
  2. Open ATAK on the device
  3. Watch the terminal — you should see CoT packets arriving 
     in the log (position reports, etc.)

If you see packets flowing, THE COT BRIDGE IS WORKING.
Press Ctrl+C to stop watching the log.


────────────────────────────────────────────────────────────────
IF THE COT BRIDGE IS NOT RUNNING OR NO PACKETS APPEAR:
────────────────────────────────────────────────────────────────

The Meshtastic radio may have locked up during boot. 
Enable the USB hub power cycle to fix this:

    sudo nano /etc/nucleus/mesh.conf

Find this line:

    USB_HUB_POWER_CYCLE=false

Change it to:

    USB_HUB_POWER_CYCLE=true

Save and exit: Ctrl+O, Enter, Ctrl+X

Then regenerate and reboot:

    sudo /opt/nucleus/bin/config_generation.sh

    sudo reboot

Wait 60-90 seconds, SSH back in:

    ssh natak@0021-nucleus.local

Password: 52235223

Run the live log again:

    sudo journalctl -u cot-bridge -f

Connect ATAK device again and confirm packets are flowing.


────────────────────────────────────────────────────────────────
CONFIRM MOSQUITTO IS DISABLED:
────────────────────────────────────────────────────────────────

After verifying the CoT bridge (Ctrl+C to stop the log), run:

    sudo systemctl status mosquitto --no-pager

Should show "inactive (dead)" or "not found". Either is fine.

================================================================
TROUBLESHOOTING
================================================================

PROBLEM: Can't SSH to the node
FIX: Make sure you're on the node's Wi-Fi AP or connected via 
     Ethernet. Try the IP address directly if .local doesn't 
     resolve.

PROBLEM: git pull fails
FIX: Check internet connection on the node. It needs WAN access 
     (Ethernet to router) to reach GitHub.

PROBLEM: CoT bridge won't start
FIX: Check if radio is detected: ls /dev/ttyACM*
     If no device found, set USB_HUB_POWER_CYCLE=true and reboot.

PROBLEM: Services look wrong after reboot
FIX: Re-run: sudo /opt/nucleus/bin/config_generation.sh
     Then reboot again.
