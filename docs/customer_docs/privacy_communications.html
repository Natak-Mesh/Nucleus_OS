Nucleus Node — Private Communications

Beyond tactical mesh networking, the Nucleus is a layered, infrastructure-independent platform for secure and clandestine communication. Everything described here works in addition to the standard ATAK-focused mesh capabilities the node already provides.

No cloud accounts. No call logs. No metadata collection. Multiple independent communication paths — if one is compromised or blocked, others continue to function. The operator controls all infrastructure.

Voice & Video — Jami + OpenDHT

Encrypted voice and video calls between any devices on the mesh. No phone company, no SIP server, no cloud accounts.

  • OpenDHT runs on every node with network isolation — your DHT is invisible to the public internet
  • Peer discovery is entirely within your network — no external observer can see who's calling whom
  • Works fully offline (verified)
  • Supports 1:1 and group encrypted messaging alongside voice/video
  • Works across Tailscale/Yggdrasil tunnels — remote nodes add each other's tunnel IPs to the bootstrap config and calls route transparently

Secure Messaging — Reticulum

Reticulum runs as a transport node on every Nucleus, bridging traffic across the mesh and providing a TCP listener for EUD apps.

  • Sideband (Android/iOS/Desktop) — secure messenger. Install on phone, point at the node's IP. E2E encrypted messaging with forward secrecy, store-and-forward delivery, file transfer.
  • LXMF — the underlying message protocol. Delivers messages even when the recipient is offline — messages propagate and deliver when the destination reappears.
  • I2P interface — built into the stack. Nodes with internet access can peer over I2P for Tor-like transport anonymity.

Packets don't reveal source addresses (initiator anonymity). Destinations are cryptographic hashes. Every link uses ephemeral keys. The protocol assumes the network is hostile.

Long-Range Text — Meshtastic LoRa

Encrypted text and GPS over LoRa radio. Multi-mile range through terrain that blocks WiFi. No infrastructure required.

  • AES-256 channel encryption — only nodes with the key can read traffic
  • Dual-transport: LoRa for range, WiFi UDP for speed between nearby nodes
  • No carrier records, no tower logs, no metadata trail
  • Web UI for messaging — no phone app required

Remote Linking — Tailscale vs. Yggdrasil

Both connect geographically separated nodes over the internet. Different tradeoffs.

TailscaleYggdrasil
Central dependencyTailscale coordination serverNone
Account requiredYes (Google/MS/etc)No — local keypair only
NAT traversalExcellent (DERP relays)Good (TCP/TLS, no relay fallback)
Traffic signatureWireGuard — detectable by DPILooks like normal TLS
SetupLogin and doneConfig file + one public peer
InfrastructureTailscale's serversYour VPS

Tailscale is the practical choice when ease of setup matters. Yggdrasil is the privacy choice — no accounts, no identity linkage, traffic blends with HTTPS, and you control all infrastructure. Both carry Jami, Reticulum, and all other services transparently.

Jami Over Tunnels

Add remote tunnel IPs to the bootstrap config:

# /etc/nucleus/mesh.conf
# Include both local mesh IPs AND remote tunnel IPs
OPENDHT_BOOTSTRAP_IPS="10.20.1.8,10.20.1.10,100.64.0.5,100.64.0.12"
#                       ^^^local mesh^^^       ^^^tailscale IPs^^^

OpenDHT connects across both local and tunnel interfaces. Jami calls route over whichever path is available.

Reticulum Over Tunnels

Add a TCP client interface pointing at the remote node or Linode:

# ~/.reticulum/config — add alongside existing interfaces

[[Remote Peer via Tailscale]]
type = TCPClientInterface
enabled = yes
target_host = 100.64.0.5       # Tailscale IP of remote node
target_port = 4242

# Or via Yggdrasil:
# [[Remote Peer via Yggdrasil]]
# type = TCPClientInterface
# enabled = yes
# target_host = 200:xxxx::1    # Yggdrasil IPv6
# target_port = 4242

Yggdrasil Implementation Path

Installed on nodes but not configured. Four steps to production:

  1. Linode anchor: apt install yggdrasil, set Listen: ["tls://0.0.0.0:443"], enable service
  2. Each node: Set Peers: ["tls://<linode-ip>:443"], enable service
  3. Verify: Nodes get 200::/7 addresses, ping across Yggdrasil IPv6
  4. Integrate: Add config to mesh.conf, start script, web UI page

Traffic on port 443 using TLS — indistinguishable from normal HTTPS to any observer.
